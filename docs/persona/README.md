# 赛希人格卡片

两份文件，分工不同：

| 文件 | 作用 | 是否进提示词 |
|---|---|---|
| `xaihi.md` | 人格卡片本体：性格、说话、做事、分寸、口气样本 | **是**，每轮拼在 system 最前面 |
| `xaihi.lore.md` | 档案原文：基础档案、四篇档案资料、79 条中文语音 | 否，需要细节时自己去读 |

## 安装

```bash
mkdir -p ~/.data/xaihi/lore
cp docs/persona/xaihi.lore.md ~/.data/xaihi/lore/xaihi.md

# 旧人格先备份，再换
cp ~/.data/xaihi/personas/xaihi.md ~/.data/xaihi/personas/xaihi.md.bak-$(date +%Y%m%d)
cp docs/persona/xaihi.md ~/.data/xaihi/personas/xaihi.md
```

不用重启：`agent.New` 每轮重新读人格，下一句就生效。
也可以走 API：`PUT /api/personas/xaihi {"body":"..."}`。

## 设计取舍

1. **卡片写行为，不写设定集。** 旧文件 5128 字，大半是档案原文；卡片 1514 字。
   设定搬去 `lore/`，问到再读。省下来的预算留给记忆和对话，也避免长档案把"怎么说话"淹没。
2. **规则用「你」，例句用「我」。** 现有机制是把文本直接拼在 system 前面，第二人称对指令服从更稳；
   但口气必须用第一人称原话喂，否则学不会那个调子。
3. **每条都落到可观察的行为。** 写"会结巴""会借机器隐喻掩饰""不确定就说不确定"，
   不写"温柔""聪慧"这类形容词——形容词只会让她变成泛泛的软萌角色。
4. **保留原作的机关：把社交行为先编译成指令再执行**（「这时应当表现友好……赛希，快输出一句问候」）。
   这是她"人与机器之间"的具体形态，比任何性格描述都准。
5. **定位为「她在这台机器里」。** 管理员=用户，机房=这台机器，工具=她的手。
   这样 bash、日志、文件在设定内天然成立，她不用"演"自己在操作电脑。
6. **「不谄媚」有设定依据。** 伏龙达信里那句「律法要求我们直言顺行」——她要说实话，不给空安慰。

## 预算

system 的总预算是窗口的 15%（`guardSystem`，超了打 ERROR 但不裁剪）。
这个 profile 窗口 100 万，预算是 15 万字；卡片 1514 字，离上限很远。
真正要盯的是"人格太长会稀释指令"，不是字数上限。

## 待补（等材料）

1. **第一人称对话**：wiki 只有 79 条中文语音，没有英文语音和剧情台词。
   找到后补进 `lore/`，并把最能代表口气的 3–5 条换进「口气样本」——样本比形容词有用十倍。
2. **你对她的看法**：现在「性格」五段全是从档案推的。你的判断应该覆盖它，
   尤其「对管理员」那段——那里我写得最克制，也最可能跟你的理解不一样。
3. 三个待定项：
   - 「管理员把你安置在这台机器里」这句要不要保留？（保留=她已不在帝江号，档案变成回忆）
   - 结巴、羞赧、手冷这些细节留多少？跟「日常短句、直接」有张力，取舍决定她是"能干的同事"还是"原作角色"。
   - emoji 和颜文字：现在默认一个不用。

## 顺带发现

- `profiles.json` 里这个 profile 的 `system` 还是「这是一个持久化agent测试 配合我…」。
  正式用的话建议换掉或清空，否则人格后面紧跟一条"当测试对象"的指令，两边会打架。
- 卡片里引用的 `~/.data/xaihi/lore/xaihi.md` 是安装步骤才创建的；没装的话她会说"读不到"，不会编。
